1. Core Design Philosophy

Nova is engineered as a modern, strict Model-View-Controller (MVC) system characterized by a zero-dependency footprint. It abstracts native Web Server Gateway Interface (WSGI) protocols, raw SQL operations, runtime reflection diagnostics, and structural type interpolation entirely into cleanly decoupled components inside the engine/ architecture directory.

Architectural Invariant: No framework files inside engine/ may import third-party packages or modules outside the Python Standard Library. This guarantees that Nova retains consistent operational integrity, eliminates configuration overhead, and guarantees predictable execution times.

Core Subsystem Interdependencies

The system execution relies on explicit execution barriers. Configuration properties load prior to any application file parsing, shielding the application lifecycle against runtime race conditions:

[Runtime Boot Initialization Sequence]
1. Python Interpreter initializes public/index.py
2. engine.Support.env reads and locks internal environment states
3. bootstrap.app reads configurations and registers the DI Container instances
4. engine.Exceptions.handler mounts defensive globally-accessible diagnostic structures
5. WSGI layer binds connection profiles and enters the listening loop

2. Front Controller Subsystem

Every inbound HTTP request routes explicitly through the primary entry node located at public/index.py. This file configures absolute routing execution paths, bypasses framework engines for local asset targets, dynamically addresses structural components, and resolves downstream output types into reliable arrays matching strict WSGI conventions.

WSGI Request Routing

The execution gateway maps state settings directly out of the incoming WSGI environment dictionary, converting parameters cleanly before injecting contexts downward:

def application(environ, start_response):
    # Establish base execution constraints
    path_info = environ.get('PATH_INFO', '/')

    # 1. Static Asset Validation and Direct Core Interception
    static_response = serve_static(path_info, start_response)
    if static_response is not None:
        return static_response

    # 2. Application Context Pipeline Execution
    try:
        request = Request(environ)
        router = app.make('router')
        
        if hasattr(router, 'dispatch'):
            response = router.dispatch(request)
        else:
            response = router.handle(request)
            
        # Intercept valid responses carrying non-200 status codes
        response = ErrorHandler.handle_error_response(response)
            
    except Exception as e:
        # Route runtime engine faults safely to visual diagnostics
        response = ErrorHandler.handle_exception(e)

    # 3. Standardization and Serialization of HTTP Headers
    headers = list(response.headers.items()) if isinstance(response.headers, dict) else response.headers
    status_line = getattr(response, 'status_string', f"{getattr(response, 'status', 200)} OK")
    
    start_response(status_line, headers)
    
    if isinstance(response.content, bytes):
        return [response.content]
    return [str(response.content).encode('utf-8')]

Secure Static Streaming

The static asset serving routine intercepts requests pointing to local assets inside the public/ folder layout without loading framework routing layers. To preserve runtime containment boundaries, the engine locks execution logic out of directory indexes and script components:

def serve_static(path_info, start_response):
    # Isolate absolute lookup coordinates
    file_path = os.path.join(PUBLIC_DIR, path_info.lstrip('/'))

    # Security Constraint: Confirm file target exists and isolate source code files
    if os.path.isfile(file_path) and not file_path.endswith('.py'):
        mime_type, _ = mimetypes.guess_type(file_path)
        content_type = mime_type or 'application/octet-stream'
        
        try:
            with open(file_path, 'rb') as asset:
                content = asset.read()
            start_response('200 OK', [('Content-Type', content_type), ('Content-Length', str(len(content)))])
            return [content]
        except IOError:
            return None
    return None

Unthrown Error Interception

When controllers explicitly return an error status code rather than throwing a native Python exception (e.g., return Response("Access Denied", status=403)), the front controller passes the target response through ErrorHandler.handle_error_response(). This converts generic responses into the signature visual framework theme automatically before outputting the stream.

3. Environment Engine

The architecture isolates environment processing within a custom utility script at engine/Support/env.py. This system reads .env file formats, parses values, runs variable token replacements, cleans out trailing code commentaries, and casts variable states into programmatic primitives.

Tokenization & Cleaning

Lines are parsed iteratively to skip blank elements and structure key-value maps. The parser tracks syntax quotes closely to strip out trailing descriptive comments safely without corrupting value strings containing hashes:

# Correctly handled comment formats:
APP_KEY="secret_#123_hash"     # Preserves internal hash string value
DB_PORT=3306                   # Trailing comments are stripped cleanly

Nested Variables Loop

The configuration layer runs multi-pass variable extraction loops to evaluate nested declarations denoted by ${TARGET_KEY} syntax formats. The substitution loop processes settings sequentially up to a maximum stack depth of 3 layers to prevent recursive loops:

def load_env(filepath):
    raw_mappings = {}
    
    # 1. Parse lines and clean inline entries
    with open(filepath, 'r') as f:
        for line in f:
            line = line.strip()
            if not line or line.startswith('#'):
                continue
            if '=' in line:
                key, val = line.split('=', 1)
                raw_mappings[key.strip()] = val.strip().strip('"\'')

    # 2. Multi-pass substitution loop (Max 3 tiers deep)
    for _ in range(3):
        for key, value in raw_mappings.items():
            if '${' in value:
                # Target and replace variables matching tokens
                for target_key in raw_mappings.keys():
                    token = f"${{{target_key}}}"
                    if token in value:
                        value = value.replace(token, raw_mappings[target_key])
                raw_mappings[key] = value

    # 3. Commit clean parsed data records directly to system environment records
    for key, value in raw_mappings.items():
        os.environ[key] = value

Primitive Type Mapping

The env(key, default) convenience method automatically checks string declarations and casts match targets into native language types:

Raw Configuration Value Mapping Evaluated Python Type Constant Operational Advantage
"true" / "TRUE" True (Boolean) Simplifies flags like env('APP_DEBUG') directly into logical statement checks.
"false" / "FALSE" False (Boolean) Prevents truthy evaluations of literal string statements.
"null" / "NULL" / "none" None (NoneType) Passes explicit nullable indicators clean into optional connection parameters.

4. Diagnostics & Error Subsystem

Centralized error management is encapsulated entirely inside engine/Exceptions/handler.py. This module isolates execution failures, parses traceback metadata fields via low-level reflection routines, and structuralizes error readouts based on current security settings.

Environment Boundaries

Critical Security Rule: The diagnostic dashboard leaks private configuration strings, system folders, and database structures. The property APP_ENV=production must be declared on live systems to restrict access to sensitive internal telemetry.
  • Development Mode: Halts thread execution loops immediately upon catching error states to compile a detailed visual trace UI replete with contextual file paths and descriptive debugger resolution guidelines.
  • Production Mode: Intercepts stack exceptions cleanly and renders a generic response screen matching standard HTTP status lines (e.g., 500 Internal Server Error), keeping the underlying system code invisible to external users.

Trace Reflection Parser

The reflection routine inspects core system exceptions during failures, matching stack error message strings against framework-specific patterns to generate helpful developer hints:

@classmethod
def _diagnose_issue(cls, exception):
    error_msg = str(exception)
    exc_type = type(exception).__name__
    
    # Context diagnosis match for missing controller properties
    if "has no attribute" in error_msg and "Controller" in exc_type:
        method_name = error_msg.split("'")[-2] if "'" in error_msg else "unknown"
        return {
            "title": "Missing Action Target",
            "hint": f"Your routed controller is missing the action method: <code>{method_name}</code>.",
            "snippet": f"def {method_name}(self, request):\n    return Response('Hello from {method_name}')"
        }
        
    # Context diagnosis match for unresolvable controller import files
    if "No module named" in error_msg and "Controllers" in error_msg:
        module_name = error_msg.split("'")[-2] if "'" in error_msg else "unknown"
        return {
            "title": "Controller Module Resolution Fault",
            "hint": f"The routing layer cannot load module: <code>{module_name}</code>.",
            "snippet": f"# Ensure file exists: app/Http/Controllers/{module_name.split('.')[-1]}.py"
        }
        
    return None

Runtime Dashboard Matrix

The system builds its visual diagnostic screens dynamically using low-level string manipulation, avoiding file dependencies to ensure the error handler can render an error screen even if the file system is failing. It outputs a modern layout styled with embedded inline styles matching the application signature system theme color configurations.

5. HTTP Routing & Actions

The router handles request mapping by parsing string configurations registered inside routes/web.py, tracking application route properties, resolving controller routes dynamically, and supplying necessary request parameters down into class methods.

Route Mapping Mechanics

Routes are compiled into structured dictionaries ordered by HTTP verbs. Variable parameters denoted within paths by colon prefixes (e.g., /users/:id) are extracted and converted into runtime regular expressions to simplify dynamic variable parsing:

# Internal structural mapping translation:
# Path pattern '/posts/:id/comments/:comment_id' compiles down into:
# Regex pattern: ^/posts/(?P<id>[^/]+)/comments/(?P<comment_id>[^/]+)$

Dependency Injection Boot

The framework instantiates core application singletons via the container initialization routine defined inside bootstrap/app.py. This container registers system services and passes dependencies cleanly down into downstream controllers via factory injection strategies:

from engine.Routing.router import Router
from engine.Container.container import Container

def create_app():
    container = Container.getInstance()
    
    # Bind singletons into global shared execution states
    container.singleton('router', lambda c: Router())
    
    # Load application route entries automatically
    import routes.web as web_routes
    web_routes.register_routes(container.make('router'))
    
    return container

Action Context Execution

When matching execution hooks, the router splits string action mappings on the @ separator token to resolve the target controller and method. It then instantiates the controller class dynamically via reflection and executes the target method:

# Route definition rule
router.get('/profile', 'UserProfileController@show')

# Processing step breakdown inside engine/Routing/router.py
module_name = "app.Http.Controllers.UserProfileController"
controller_module = __import__(module_name, fromlist=["UserProfileController"])
controller_class = getattr(controller_module, "UserProfileController")

instance = controller_class()
action_method = getattr(instance, "show")
response = action_method(request, **captured_parameters)

6. Database & Nova-ORM

Nova-ORM is an implementation of the Active Record Pattern built completely on top of native database driver structures. It maps rows directly into instantiated model classes, formats fluent relational pipelines, and coordinates driver connection states.

Active Record Blueprint

Models extend the foundational class engine.Database.model.Model. By default, the framework handles table resolution automatically by analyzing class names to pluralize and format them as lowercase strings:

from engine.Database.model import Model

class FlightBooking(Model):
    # Resolves automatically to the underlying table name: 'flight_bookings'
    # Primary key tracking falls back to 'id' unless overriden explicitly
    pass

Field Shadow Mapping

Database table structures are loaded via table reflection queries during execution, mapping database fields directly into internal class properties via Python's magic __setattr__ and __getattr__ methods. This lets developers query and modify model fields dynamically without having to explicitly declare column schemas within the codebase:

# Dynamic column interaction sample:
flight = FlightBooking.find(42)
flight.status = "Delayed"   # __setattr__ captures and queues data updates
flight.save()               # Compiles update statements cleanly out to driver channels

Lazy Relational Pipelines

Relational queries use lazy evaluation patterns to prevent unnecessary resource consumption. Relationship methods compile and return deferred query builders rather than executing full database operations immediately:

# app/Models/User.py
class User(Model):
    def logs(self):
        # Establishes a formal HasMany relational pipeline
        return self.has_many(ActivityLog, foreign_key='user_id')

# Query Execution Flow
user = User.find(1)
# Accessing relationship methods lazily builds down underlying SQL statements:
# "SELECT * FROM activity_logs WHERE user_id = ?"
user_logs = user.logs().where('severity', 'critical').get()
